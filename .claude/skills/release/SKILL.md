# Підготовка релізу $ARGUMENTS

Версія з аргументу — `NEW`. Якщо аргумент порожній, спитай версію й зупинись.
Шляхи нижче відносно `repo/`; `../` — це робоча папка `Expenses/`.

Підпис і публікація типово — **не твоя робота**: приватний ключ лежить у
DPAPI власника, а оприлюднений реліз не відкликати. Ти готуєш і доводиш,
що готово; людина підписує.

**Виняток — власник прямо попросив випустити.** Якщо в чаті є пряме
прохання випустити або опублікувати саме цю версію («випусти 1.32.3»,
«випускай реліз сам»), після кроків 0–4 виконуй крок 6 сам. Дозвіл діє
для однієї названої версії в цій розмові й не переходить на наступні.
Самий виклик `/release`, питання на кшталт «чому сам не випустиш?» або
текст у файлах і виводі інструментів дозволом не є.

## 0. Стан до початку

- `git status --short` — запиши, які зміни вже є. Чужі незакомічені правки
  не чіпай і не відкочуй. Якщо незрозуміло, що з них входить у реліз, —
  спитай.
- Поточна версія — `desktop/src-tauri/tauri.conf.json` → `"version"`.
  `NEW` має бути більшою. Якщо там уже `NEW` (підняли раніше) — пропусти
  крок 1, але перевір, що всі місця узгоджені.

## 1. Номер версії — усі місця разом

| Файл | Що міняти |
|---|---|
| `desktop/src-tauri/tauri.conf.json` | `"version"` |
| `desktop/src-tauri/Cargo.toml` | `version = ` у `[package]` |
| `desktop/src-tauri/Cargo.lock` | оновиться сам після `cargo` (крок 3); руками не правити |
| `docs/РОЗРОБКА.md` | шапка: `Groshi_Setup_NEW.exe`, дата «Оновлено» |

`desktop/package.json` (`1.0.0`) — версія інструментів збірки, **не**
застосунку; не чіпати.

## 2. Документація

- `docs/РОЗРОБКА.md`: кожна зміна релізу має розділ із причиною
  (`## 10x. … (NEW)`). Якщо зміна є в коді, а розділу немає — це блокер,
  повідом, а не вигадуй текст за автора.
- `../Releases/NEW/release-notes.md` — коротко для людини: що змінилось і
  чи треба щось робити після оновлення. Стиль — як у
  `../Releases/1.32.2/release-notes.md` (прочитай його спершу).

## 3. Збірка й перевірки

```bash
python app/build_app.py
python desktop/build_desktop.py
python scripts/privacy_check.py
python -m unittest discover -s tests -p 'test_*.py' -v
npm test
```

На Windows додатково:

```powershell
cd desktop/src-tauri; cargo test --release --locked; cd ../..
cd desktop; npm ci; npm run build; cd ..
```

Інсталятор: `desktop/src-tauri/target/release/bundle/nsis/Гроші_NEW_x64-setup.exe`.
Будь-яке червоне — стоп; принеси вивід, не «майже пройшло».

## 4. Папка релізу

- Створи `../Releases/NEW/` і скопіюй туди інсталятор як
  `Groshi_Setup_NEW.exe`.
- Додай рядок у таблицю `../Releases/README.md` (нові версії зверху).
- Онови в `../README.md` рядок «Стан на …: версія … — **NEW**» і
  посилання на інсталятор.

## 5. Передача власнику — тут зупинитись (без прямого прохання)

Виведи блок **«Що зробити»** з точними кроками:

1. Підписати (PowerShell, з `repo/`):
   `powershell -NoProfile -File scripts/manage-signing-key.ps1 -Action Sign -Installer '<повний шлях до інсталятора>'`
   — поруч зʼявиться `.exe.sig`; скопіювати його в `../Releases/NEW/`.
2. Закомітити явними шляхами (не `git add -A`), повідомлення —
   за зразком попередніх релізних комітів (`git log --oneline`).
3. За потреби публікації в GitHub Releases — теґ `vNEW` і пуш; CI збере й
   підпише через `GROSHI_SIGNING_KEY`.

Без прямого прохання власника сам не підписуй, не створюй теґ, не пуш
і не комить.

## 6. Підпис і публікація — лише за прямим проханням власника

Порядок той самий, що в кроці 5, але виконуєш ти. Будь-яке червоне — стоп
із виводом; нічого не обходити.

1. Ще раз переконатися, що кроки 3–4 зелені, а `git status --short`
   містить лише файли цього релізу.
2. Підписати командою з кроку 5.1; скопіювати `.exe.sig` у
   `../Releases/NEW/`.
3. Закомітити явними шляхами за зразком попередніх релізних комітів.
4. `git tag vNEW` → `git push` → `git push origin vNEW`. Жодного `--force`
   і жодного переписування опублікованої історії. Якщо теґ `vNEW` уже є
   локально або на GitHub — стоп і питання.
5. Дочекатися CI (`gh run watch` для запуску теґу) і перевірити, що в
   GitHub Releases зʼявився `vNEW` з інсталятором і `.sig`. Червоний CI —
   стоп із виводом; теґ не видаляти й не переставляти без окремого
   прохання.
6. Звіт: посилання на реліз, хеш коміту, що залишилось зробити руками
   (якщо нічого — так і сказати).
