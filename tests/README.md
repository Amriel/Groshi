# Проби

Сценарії на Playwright: відкривають зібраний файл, роблять те саме, що
робила б людина, і друкують результат. Кожна написана під конкретний
випадок і лишилась у репозиторії як сторож — щоб та сама поломка не
повернулась тихо.

```bash
npm install playwright && npx playwright install chromium
python3 app/build_app.py          # проби працюють із ЗІБРАНИМ файлом
node tests/allcheck.mjs
```

Якщо chromium уже є в системі, шлях до нього можна передати змінною:
`CHROMIUM=/usr/bin/chromium node tests/allcheck.mjs`. Якщо `playwright`
встановлено поза репозиторієм (наприклад, у робочій теці без власного
`node_modules`), шлях до модуля задає
`PLAYWRIGHT_MODULE=/шлях/до/node_modules/playwright`. Обидві змінні читають
усі проби з таблиці нижче, крім `pjstat.mjs` і `v1311.mjs`: вони
імпортують `playwright` напряму й `PLAYWRIGHT_MODULE` ігнорують.

Повний набір: `npm test` (так само його запускає CI). Python-тести:
`python -m unittest discover -s tests -p 'test_*.py' -v`.

**Штучні дані.** `node tests/helpers/synthetic.mjs` пише штучний набір
`.test-artifacts/synthetic.json`, а `python app/build_app.py --data
.test-artifacts/synthetic.json --out .test-artifacts/synthetic_app.html` збирає
з ним окремий HTML. `npm test` робить обидва кроки сам (`pretest`) — на цьому
файлі працюють `nostripe`, `overflow` і знімки. Окремо запущена проба читає вже
зібраний файл, тож після зміни шаблону його треба перезібрати (або запустити
`npm test`).

**Знімки, не проби.** `node tests/snap.mjs <мітка>` робить 42 знімки
(7 вкладок × 2 теми × 3 ширини) у `.test-artifacts/snap-<мітка>/`. Це
інструмент для порівняння вигляду до й після змін, він нічого не стверджує й у
`npm test` не входить. `SNAP_DESKTOP=1 node tests/snap.mjs <мітка>` знімає те
саме з десктопної збірки (`python desktop/build_desktop.py`) зі штучними
інвестиціями й операціями (`tests/helpers/desktop-boot.mjs`) і додає знімки
всієї сторінки `<тема>-<ширина>-inv-full.png`: у браузерній збірці
«Інвестиції» — лише заглушка. У цьому режимі неочікувані IPC-команди
(`window.__unexpectedCommands`) — помилка, як і винятки сторінки.

## Python-тести (`test_*.py`)

Запускаються в CI кроком `unittest` перед `npm test`.

| Тест | Що сторожить |
|---|---|
| `test_build_security.py` | штучні дані не ламають структуру зібраного HTML; CSP іде перед ресурсами; хеш скрипта залежить від приватного знімка |
| `test_privacy_check.py` | `scripts/privacy_check.py` відхиляє приватні файли й секрети (не друкуючи значень), пропускає порожні публічні seed-файли |
| `test_stale_index.py` | `scripts/stale_index_check.py` блокує коміт, що повертає файл назад через відсталий індекс |
| `test_mononorm_sync.py` | `mcp/mononorm.js` дорівнює джерелу `desktop/dist/mononorm.js`; мовчазний дрейф дав би різні категорії в апці та MCP |
| `test_pseudo_sync.py` | `desktop/dist/pseudo.js` дорівнює джерелу `mcp/pseudo.js` (різниця лише в EOL ігнорується); дрейф дав би різні псевдоніми в апці та MCP |

Проби, що потребують реального Flex-звіту IBKR, у репозиторій не
включені: вони працюють із приватними даними автора.
