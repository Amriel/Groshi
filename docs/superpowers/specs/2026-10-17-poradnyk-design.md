# Порадник — AI-агент усередині «Грошей» (дизайн)

**Дата:** 2026-10-17 · **Статус:** чернетка на погодження власником

Позначки: **[власник]** — вирішив власник у розмові; **[моє]** — рішення
автора документа, власник може перекинути; **[будівельнику]** — свідомо
лишено тому, хто будує.

## 1. Навіщо

Власник регулярно відчуває, що «забагато грошей іде в місяць», і хоче
ставити звичайні питання до своїх же даних, а не до загальних порад з
інтернету. Три головні питання **[власник]**:

1. «Які основні мої витрати?» — куди йдуть гроші, з цифрами й динамікою.
2. «Як скоротити витрати?» — конкретні місця економії з оцінкою «скільки
   це дасть на місяць» (підписки, категорії, що виросли, дрібні часті
   покупки, що складаються у велику суму).
3. «Куди краще інвестувати зараз?» — розбір фактичного портфеля
   (IBKR, Binance): концентрація, валюти, гроші без діла, і варіанти з
   плюсами й ризиками.

Успіх: відповідь спирається на реальні цифри з даних застосунку, які можна
перевірити в інших вкладках, і дає дію, яку можна зробити.

## 2. Цілі, не-цілі, анти-цілі

  - **API Anthropic** — запасний, мінімум налаштувань **[власник]**.
- Якісна інструкція (системний промпт), особливо для локальної моделі
  **[власник]**, яку можна переглянути й підправити в застосунку **[моє]**.
- Захист NDA-даних при відправці в хмару (§6) **[власник]**.

**Не-цілі (v1)**
- Порадник нічого не змінює в даних: не категоризує, не створює правил,
  не чіпає рахунків. Лише читання **[моє]**.

- Довільне читання вебсторінок (`WebFetch`) — поза v1, свідомо.
- Ollama, OpenAI та інші хмарні провайдери — поза v1. Локальний шлях
  будується на OpenAI-сумісному API, тож Ollama потім додається адресою
  **[моє]**.
- Автоматичні щотижневі звіти, сповіщення від порадника — поза v1.

**Анти-цілі (провал, навіть якщо «працює»)**
- Порадник називає суми, яких немає в даних (вигадані цифри).
- Назва клієнта ФОП, проєкту чи контрагента з рахунку пішла в хмару.
- Ключ API потрапив у JS, localStorage, `state.json`, журнал або чат.
- Запущений `claude` має доступ до файлів, терміналу, `WebFetch` чи інших
  MCP, крім «Гроші» на читання й `WebSearch`.
- Інвестиційна відповідь звучить як «купіть X» без ризиків і застереження.
- Вкладка «смикається» під час потокової відповіді (правило проєкту).

## 4. Архітектура

### 4.1. Головне правило
Уся мережа й усі процеси — **у Rust**. CSP вебвʼю не розширюємо **[моє]**:
так `native_csp.rs` лишається чинним, а ключ ніколи не потрапляє в JS.

### 4.2. Інструменти даних — одне джерело
`mcp/groshi-mcp.js` розділити на чисту бібліотеку інструментів (наприклад
`mcp/tools.js`: опис, схема, `run()`) і тонку stdio-обгортку **[моє]**.
Поведінка зовнішнього MCP для Claude Desktop не змінюється.
Порадник **для всіх трьох способів** користується саме цими інструментами,
щоб числа збігались із MCP і між провайдерами.

Як інструменти доходять до моделі:
- **Claude Code:** `claude` сам запускає наш MCP через `--mcp-config`.
- **API і локальна модель:** Rust запускає той самий MCP-сервер як
  дочірній процес Node і говорить із ним JSON-RPC (мінімальний MCP-клієнт:
  `tools/list`, `tools/call`). Цикл «модель → виклик інструмента →
  результат → модель» крутить Rust **[моє]**.

Залежність від Node (вже потрібна зовнішньому MCP) для порадника
приймається **[моє]**: застосунок персональний, Node встановлено. Файли MCP
мають їхати разом з інсталятором (ресурси Tauri) — як саме, **[будівельнику]**.
Якщо Node не знайдено — зрозуміле повідомлення у вкладці.

### 4.3. Коротке зведення («пакет даних»)
Перед кожною новою розмовою застосунок складає коротке текстове зведення
з уже наявних у ньому даних: період, витрати по топ-категоріях за останні
3 місяці й середнє, зміна до попередніх, підписки на місяць, доходи,
залишки, склад портфеля й частки **[моє]**. Воно йде в системний промпт.

Навіщо: локальна модель не мусить сама рахувати (менше вигадок), а Claude
одразу має контекст і лише уточнює інструментами. Зведення проходить ту
саму знеособлювалку, що й інструменти (§6). Де саме його рахувати
(JS у вебвʼю з `TX`, чи новий інструмент `advisor_digest` у `tools.js`) —
**[будівельнику]**.

Умова збігу **[моє]**: зведення рахується за останні 3 повні календарні
місяці з **поточними налаштуваннями власника** (режим руху коштів
`moveMode`, особисті виключення, ручні категорії) — так само, як «Огляд»
за той самий період. Перевірка: на штучних даних сума витрат місяця у
зведенні = сума в «Огляді» за цей місяць. Якщо наявні інструменти MCP
(`money_flow`, `transactions`) дають інші числа, ніж «Огляд», — це
задокументувати й винести окремою задачею; у етап 1 зведення MCP не
входить, але в інструкції сказати моделі: «для підсумків довіряй
зведенню, інструменти — для деталей».

### 4.4. Три способи підключення

**A. Claude Code (перший етап).**
Rust запускає встановлений `claude` у режимі `-p` з потоковим JSON-виводом,
власним системним промптом і MCP-конфігом лише з «Гроші».
Обовʼязково **[моє]**:
- дозволені лише інструменти `mcp__groshi__*` і `WebSearch` (§4.4а);
  решта вбудованих (файли, термінал, `WebFetch`, субагенти) заборонені явно, а не «покладаємось на неінтерактивний режим»;
- `--strict-mcp-config` або еквівалент — жодних інших MCP користувача;
- робоча тека — окрема порожня тека порадника в теці даних, щоб не
  підтягувався чужий CLAUDE.md, скіли чи хуки проєкту;
- продовження розмови — через `--resume <session_id>` з потокового виводу;
- зупинка — вбити процес (кнопка «Стоп»).
Ізоляція від налаштувань користувача **[моє]**: глобальний
`~/.claude/CLAUDE.md` користувача може мати власні правила роботи
і не повинен потрапляти в порадника. Шукати прапорці, що відсікають
user/project-налаштування, але зберігають вхід за підпискою (вхід —
окремо від налаштувань). Якщо повністю відсікти не вдається — прийняти
глобальний CLAUDE.md, але вбудовані інструменти й субагенти однаково
заборонені, а системний промпт порадника прямо каже ігнорувати сторонні
правила роботи; задокументувати це в РОЗРОБКА.md. Блокувати спосіб через
це не треба.
Пошук `claude`: PATH, потім відомі місця WinGet/npm. Не знайдено або не
залогінено → підказка у вкладці («встановіть Claude Code / виконайте
`claude` і увійдіть»). Вибір моделі (`--model`): за замовчуванням не
передавати, у налаштуваннях вкладки можна вказати **[моє]**.

**B. Локальна модель (другий етап).**
OpenAI-сумісний `POST /v1/chat/completions` зі `stream: true`. Адреса за
замовчуванням `http://localhost:1234/v1` (LM Studio), змінна в
налаштуваннях вкладки; дозволено лише `localhost`/`127.0.0.1`/`[::1]`
**[моє]** — щоб «локальна» модель не стала тихо хмарною без знеособлення.
Список моделей — `GET /v1/models`, вибір — `.csel`.
Інструменти: перемикач «з інструментами / лише зведення». За замовчуванням
— з інструментами (сучасні локальні моделі вміють tool calling); якщо модель їх не
підтримує або плутається — лише зведення **[моє]**.
Сервер вимкнено → підказка «запустіть сервер у LM Studio (або
`lms server start`)».

**C. API Anthropic (третій етап).**
Messages API зі стрімінгом і tool use, цикл інструментів у Rust (§4.2).
Ключ — у Диспетчері облікових даних (`broker_entry("anthropic-key")`),
трійка команд `has/set/clear` за зразком IBKR/Binance; ключ у JS не
повертається ніколи. Модель — за замовчуванням актуальна Sonnet, змінна
**[моє]**. Ліміт кроків циклу інструментів (наприклад 8) — захист від
нескінченного циклу **[моє]**.

### 4.4а. Ринок і новини
**[власник: «з пошуком новин 100% + аналіз стану ринку 100%»]** Для
питання «куди інвестувати зараз» порадник має бачити поточний стан ринку.

- **Claude Code:** дозволити вбудований `WebSearch` на додачу до
  `mcp__groshi__*`. `WebFetch` (довільні адреси) — **заборонено** **[моє]**:
  сторінка з інʼєкцією могла б змусити модель вставити дані в URL.
  Пошукові запити — загальні (ринок, ставки, тикери), без особистих даних;
  це правило — в інструкції.
- **API:** серверний інструмент веб-пошуку Anthropic (web search tool)
  з обмеженням кількості пошуків на відповідь **[моє]**.
- **Усі способи, включно з локальним:** власний інструмент «ринок» на
  даних, які застосунок уже вміє тягнути з Rust (Yahoo-котирування й
  новини по тикерах — `quotes_today`, `quote_news`, `quote_detail`;
  курси НБУ): основні індекси, курси UAH, рух і новини по паперах
  портфеля **[моє]**. Для API й локальної моделі це Rust-інструмент у
  циклі; для Claude Code — те саме, що й у MCP, якщо дані вже в кеші на
  диску (MCP мережі не має й не отримує). Точний набір індексів і
  новин — **[будівельнику]**.
- Локальна модель вебу не має: у відповіді вона спирається на інструмент
  «ринок» і прямо каже, що ширших новин не бачила.
- Відповідь про ринок завжди містить дату даних («станом на …»).

Це навмисно розширює мережевий доступ порадника — ревʼю Rust-частини
перед злиттям обовʼязкове (мережа + секрети).

### 4.5. Потік у вкладку
Rust шле події з фрагментами тексту, викликами інструментів (для показу
«дивлюсь операції за вересень…») і кінцем/помилкою; одна команда «стоп».
Зразок — `sync`/`sync_stop`. Формат подій — **[будівельнику]**.

## 5. Інструкція порадника

Одна **спільна** інструкція для всіх способів + **додаток** для локальної
моделі **[власник: «якісна інструкція»; структура — моє]**.

Спільне ядро:
- роль: особистий фінансовий аналітик власника, українська мова;
- які дані є і які інструменти за ними;
- порядок відповіді: спершу цифри з даних (з періодом), потім висновок,
  потім 1–3 конкретні дії з оцінкою ефекту в ₴/міс;
- **не вигадувати чисел**: кожна сума — з інструмента або зведення; якщо
  даних нема — так і сказати;
- перекази людям і «Між рахунками» — не одне й те саме (див. виправлення
  «На картки» від 17.10.2026); готівка — не витрата на щось конкретне;
- інвестиції: аналіз портфеля й варіанти з плюсами й ризиками, без «купіть
  X»; коротке застереження, що це не ліцензована порада;
- псевдоніми «Клієнт N»/«Проєкт N» — звичайні назви, не коментувати їх.

Додаток для локальної моделі: суворіший формат (короткі розділи, таблиця
цифр), явна вимога спершу перечитати зведення, приклади добрих відповідей
на три головні питання, заборона довгих міркувань у відповіді.

Інструкцію видно й можна редагувати в налаштуваннях вкладки, з кнопкою
«повернути стандартну» **[моє]**. Зберігається в стані застосунку.

- відповідь моделі у вкладці показується зі справжніми назвами: застосунок
  підставляє їх назад локально; словник замін нікуди не відправляється;
- у заголовку розмови видно режим: «хмара · назви приховано» або
  «локально» (бейдж, не кольорова смуга).

Тест-сторож: на штучних даних жодна назва клієнта/проєкту не трапляється
у тексті, що йде в хмарний процес (вивід MCP із прапорцем + зведення).

Інше:
- **спосіб підключення закріплюється за розмовою** **[моє]**: змінити його
  посеред розмови не можна, лише почати нову. Інакше локальна розмова
  зі справжніми назвами пішла б у хмару, а `--resume` Claude Code все
  одно не переноситься між провайдерами. Локально історія зберігається
  зі справжніми назвами (як бачить власник);
- історія розмов — локально, окремим файлом у теці даних (не в
  `state.json`, щоб той не розростався) **[моє]**; файл додати до
  шаблонів `scripts/privacy_check.py`;
- ключ API — лише Диспетчер облікових даних;
- MCP «Гроші» лишається лише для читання; порадник не отримує коду запису.

## 7. Вкладка «Порадник» (UI)

- Окрема вкладка перед «Ще» **[власник: окрема вкладка; місце — моє]**.
  Гарячі клавіші стають `1–8`, «Ще» — `8`; оновити довідку `?`.
- Верх: перемикач способу (`.csel`: Claude Code / Локальна / API),
  бейдж режиму приватності, кнопка «Нова розмова», список минулих
  розмов (відкрити / видалити через `uiConfirm`).
- Порожня розмова: три кнопки-підказки — «Куди йдуть гроші»,
  «Як скоротити витрати», «Що з портфелем».
- Повідомлення: текст моделі з простим Markdown (заголовки, списки,
  таблиці, жирний), суми в стилі застосунку; під відповіддю — дрібний
  підпис моделі (яка саме відповідала), щоб порівнювати якість.
- Під час відповіді — рядок «дивлюсь: операції за вересень…» з викликів
  інструментів; кнопка «Стоп».
- Налаштування способу (адреса LM Studio, модель, ключ API, інструкція) —
  у розкривному блоці вкладки або в «Ще» — **[будівельнику]**, за
  наявними примітивами (`uiAsk`, `buildCombo`, `.csel`, власний checkbox).
- Правила проєкту: жодного системного вигляду; потік дописується в
  останнє повідомлення на місці, без `innerHTML =` усього списку; ширини
  змінного тексту зафіксовані; жодних кольорових смуг збоку карток.

## 8. Етапи

1. **Основа + Claude Code:** розділ MCP на `tools.js` + обгортку,
   знеособлювач, зведення, Rust-запуск `claude` зі стрімом і стопом,
   вкладка з чатом, історія, інструкція.
2. **Локальна модель:** OpenAI-сумісний клієнт у Rust, MCP-клієнт у Rust,
   цикл інструментів, перемикач «лише зведення», додаток до інструкції.
3. **API:** ключ у Диспетчері, Messages API зі стрімом і tool use на тому
   ж циклі.

Кожен етап — окремо робочий і окремо перевірений.

## 9. Перевірки

- Python/Node-тест знеособлювача на штучних даних (анти-ціль №2).
- `tests/test_mononorm_sync.py`-подібний сторож, якщо `tools.js` має
  копію (MCP-тека для Claude Desktop) — **[будівельнику]**.
- Playwright-проба `advisor.mjs` з підробленим провайдером (через
  `__DESK__`): вкладка відкривається, підказки шлють питання, потік
  дописується без зрушень, «Стоп» працює, браузерна збірка показує
  заглушку. Плюс наявні `allcheck`, `modal`, `pjjump`, `nav`.
- `cargo test`: запуск `claude` збирає аргументи з дозволом лише
  `mcp__groshi__*`; адреса локальної моделі не-localhost відхиляється;
  ключ не повертається жодною командою.
- `native_csp.rs` лишається без змін.
- Ручна перевірка власником: ті самі три питання на Claude Code і
  локальній моделі.
