# Дані для Порадника — план реалізації

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Мета:** апка, зведення Порадника й MCP показують ті самі цифри; Порадник
отримує категорії по місяцях, мітки переказів, нотатки й дати списань.

**Архітектура:** апка (`app/app.template.html`) збирає всі цифри однією
функцією `advData()`; з неї форматується зведення й записується знімок
`advice_cache.json` (десктоп, команда Tauri `advice_cache_set`). MCP
(`mcp/tools.js`) читає знімок і нічого не перераховує.

**Стек:** ванільний JS у шаблоні, Rust/Tauri, Node MCP, проби Playwright.

**Спека:** `docs/superpowers/specs/2026-10-30-advisor-data-design.md` —
читати разом із цим планом.

## Глобальні обмеження

- Інтерфейс змінюється лише в `app/app.template.html`; після кожної зміни —
  `python app/build_app.py` і `python desktop/build_desktop.py`.
- Жодного системного вигляду: без `prompt/confirm/alert`, нативного
  `<select>`, `title`, системного checkbox. Чипи — власні кнопки.
- Колір мітки — лише в бейджі/чипі/крапці; без `border-left`, без тонування
  рядка чи картки (сторожить `nostripe.mjs`).
- Нічого не смикається: перемальовувати на місці, звіряти
  `getBoundingClientRect()`.
- MCP лишається лише для читання: жодного `fs.write*` у `mcp/`.
- Коментарі — українською й пояснюють «чому».
- Проби працюють лише на штучних даних (`tests/helpers/synthetic.mjs`).
- Субагенти не комітять і не роблять `git add -A`/`.`: повертають список
  змінених шляхів; коміт робить головний цикл явними шляхами.
- Кожна задача оновлює свій розділ `docs/РОЗРОБКА.md` і дату «Оновлено».

## Формат знімка (спільний для задач 3–5)

`advice_cache.json`, усі суми — числа в гривні без форматування:

```js
{ v: 1, built: '2026-10-30T12:00:00Z', today: '2026-10-30', app: '1.34.3',
  moveMode: 'count', dmax: '2026-10-29', base: 'UAH',
  months: [ { ym: '2026-05', full: true,
              exp, inc,          // як «Огляд»: sum(rows,'expense'/'income')
              moves,             // «Між рахунками», списання (обіг)
              invest,            // «Інвестиції», списання
              people, cash } ],  // витрати «Перекази» і «Готівка» (уже входять в exp у режимі count)
  cats: [ { k: 'Продукти', byM: { '2026-05': 1234 }, n: 5, med, min, max,
            top: [ { date, amt, merchant } ],             // до 3
            subs: [ { k, byM, n, med, min, max } ] } ],
  tags: { debt: { '2026-05': 5000 }, rent: {}, family: {}, gift: {} },
  subs: [ { name, amount, famt, ccy, period, last, next, live, perMonth } ],
  tx: { '<id>': { c, s, k, a, tag, note,                 // k: spend|refund|income|move|invest|excluded|other
                  raw: { date, dir, amount, merchant, account } } } }  // raw — лише для не-Monobank (manualTx/privatTx)
```

Місяці: 6 повних + поточний (`full:false`). `tx`: операції за останні
13 місяців. `cats`: категорії з `exp > 0` хоча б в одному з 6 повних місяців,
`n/med/min/max` рахуються за 6 повними місяцями (місяці без витрат — нулі
в медіані).

## Ризики для рецензента

1. Режим `moveMode='count'` при `Між рахунками` — головна зміна чисел; має
   діяти в `isSpend`, `isIncome`, `isRefund` однаково (інакше переказ
   рахується однобоко — див. коментар біля `isIncome`).
2. Знімок без апки, що давно не відкривалась: MCP мусить попередити, а не
   мовчки віддати старі цифри.
3. Операція з ручною категорією `Інвестиції` чи `Між рахунками` (через
   `txCats`) має поводитись так само, як через правило.
4. Мітка на операції, яку згодом перекатегоризували з «Перекази» в іншу
   категорію: мітка лишається в даних, але чипи не показуються; у знімку
   мітка все одно йде.
5. Порожня апка (нуль операцій): `advData()` і знімок не падають.
