# Гроші — десктопна версія

Tauri 2 · Rust + WebView2. Один інсталятор, дані на диску, банк напряму.

## Встановлення

Запустіть **`Groshi_Setup_1.31.7.exe`**.

Ставиться для поточного користувача, без прав адміністратора, у
`%LOCALAPPDATA%\Гроші`. Інсталятор не підписаний — SmartScreen покаже
«Windows захистила ваш ПК»: «Докладніше» → «Виконати в будь-якому разі».

Потрібен **WebView2** — на Windows 10/11 він уже стоїть; якщо ні,
інсталятор завантажить його сам.

## Перший запуск

1. Апка відкриється з історією з Notion — 865 операцій. Вона вшита
   в інсталятор, щоб не починати з порожнього екрана.
2. **Ще → Monobank** → вставте токен із `api.monobank.ua` → «Підключити».
   Токен читає лише виписку; платежі ним технічно неможливі.
3. Позначте рахунки (за замовчуванням — усі гривневі картки).
4. **«Завантажити історію»** — апка спершу порахує, скільки це триватиме,
   і запропонує глибину: місяць, 3, 6, рік, 2 роки. Банк віддає один
   запит на 60 секунд, тож рік по восьми рахунках — це близько півтори
   години. Спершу приходить останній місяць по всіх рахунках, далі
   глибина; зупинити можна будь-коли, завантажене лишиться. Вікно можна
   закрити — апка працює у треї.
5. Далі досить кнопки **«Оновити»** — вона бере лише нове.

**Валютні рахунки** можна брати нарівні з гривневими: суми переводяться
в гривню за курсом банку на день операції. Курс апка вивчає з ваших же
гривневих покупок у валюті — стороннього джерела курсів їй не потрібно.
У списку під гривневою сумою дрібним написано оригінал (`120,00 $`).

## Оновлення

**Ще → Оновлення → Перевірити.** Апка дивиться в теку, куди складаються
збірки (теку задає користувач у налаштуваннях), знаходить
новішу й пропонує встановити: закривається, запускає інсталятор, той
оновлює програму поверх. Дані, підписки, примітки й токен лишаються —
вони живуть окремо від програми.

У теці достатньо просто мати новіший `Groshi_Setup_x.y.z.exe`: версія
читається з імені. `latest.json` поруч необовʼязковий — він лише додає
опис змін:

```json
{"version":"1.31.7","file":"Groshi_Setup_1.31.7.exe","notes":"що нового"}
```

Замість теки можна вказати адресу в мережі — тоді `latest.json` обовʼязковий,
і файл береться поруч із ним.

Штатний updater Tauri тут не використано навмисно: він вимагає підписаних
збірок і постійно доступного сервера з маніфестом. Ні того, ні того немає.

## Де лежать дані

`%APPDATA%\Гроші\` (кнопка «Показати теку з даними» у налаштуваннях):

| Файл | Що |
|---|---|
| `mono_raw.json` | сирі відповіді банку, як прийшли. Ніколи не переписуються |
| `state.json` | налаштування, підписки, примітки, кошториси |
| `legacy.json` | знімок із Notion |

Токен **не лежить у файлах** — він у Диспетчері облікових даних Windows
(`Панель керування → Облікові записи → Диспетчер облікових даних →
Облікові дані Windows → Groshi`).

Бекап = скопіювати теку. Перенести на інший комп'ютер = покласти теку
на місце й ввести токен заново.

## Само оновлення

**Ще → Застосунок → «Оновлювати самому»**: ніколи / 30 хв / година / 3 /
6 / раз на день. Апка забирає лише нове, поки сидить у треї — вікно для
цього відкривати не треба. Поруч видно час останньої спроби, а якщо
щось пішло не так — саму помилку.

## Рахунки й курс

На **Огляді** — картка «Рахунки», розбита на **ФОП**, **Картки** й
**Банки**: перші гроші оборотні, другі свої, і мішати їх в один
стовпчик означає щоразу перечитувати список. У кожної групи своя сума.

Головна сума завжди справа, в одній колонці однакової ширини; сірий
переклад у гривню й курс — ліворуч від неї. Картка згортається кліком
по заголовку, загальна сума лишається в шапці.

Курс береться з банку (`api.monobank.ua/bank/currency`, без токена) і
кешується на годину.

## Сповіщення

Нагадування про підписки показує **сама апка** через центр сповіщень
Windows — вікно для цього відкривати не треба, досить щоб вона сиділа
в треї. Кнопка «Перевірити сповіщення» шле тестове просто зараз.
Експорт у календар лишається для телефона.

## Операції з інших джерел

**Операції → «+ Операція».** Готівка, інший банк, борг — усе, що не
проходить через Monobank. Вікно питає назву, суму (у поточній валюті
показу — зберігається в гривні за курсом), дату, категорію з
підкатегорією і чекбокс «це надходження». Такі записи мають позначку
«додано вручну» в картці, беруть участь у всіх підсумках нарівні з
банківськими і видаляються кнопкою в картці. Оновлення з банку їх не
чіпає.

## Розгортання на Огляді

**«Куди йдуть гроші»**: категорія → підкатегорії → операції → повна
картка операції — все на місці, без переходу в «Операції». У
«Операції» веде лише хвостик «показати всі», коли операцій більше 25.

**«Топ мерчантів»**: клік по мерчанту розгортає всі його операції за
період, теж із карткою на місці.

## Скло

Світло тепер рахує сам шейдер із тих самих прямокутників, що й плити —
жодних карт світла, кешів і «доїздів»: тіні зшиті з вмістом у кожному
кадрі за побудовою. Перемикання вкладок ~20 мс, і після нього не
змінюється жоден піксель (перевіряється пробою попіксельно).

## Своя категорія

У картці операції: **Категорія → змінити**. Вікно питає категорію й
підкатегорію (обидві з підказками з наявних) і має чекбокс «застосувати
до всіх таких».

Третє поле — **«Застосувати до всіх, чия назва містить»**. Апка сама
підставляє спільну частину: для «CLOUDRUN* 5V5FYU5», «CLOUDRUN* GLWFJ0G»
це буде «CLOUDRUN», і під підписом одразу видно, скільки операцій
зачепить — «Зміниться 19 операцій (16 різних назв, 12 400 ₴)».

* поле порожнє — змінюється лише ця операція;
* поле заповнене — створюється правило, яке спрацює й на платіж, що
  прийде наступного місяця.

Поруч зʼявляється «скинути» — повертає те, що визначила апка.
Скільки операцій позначено вручну, видно в **Ще → Власні категорії**.

## Кілька операцій разом

Правило за назвою покриває «усі CLOUDRUN», але не покриває «оці сім
штук, які я знаю в обличчя». Для другого — **Операції → «Вибрати
кілька»** (кнопка праворуч у рядку сортування).

* клац по рядку — позначити; **Shift+клац** — увесь діапазон між;
* **«Обрати всі знайдені»** бере весь результат пошуку й фільтрів,
  а не лише показані 60 рядків — звузьте пошуком і беріть усе;
* **«Змінити категорію»** питає категорію й підкатегорію один раз і
  ставить їх усім обраним. Правило за назвою при цьому **не**
  створюється: вибір зроблено руками, майбутніх платежів це не
  стосується;
* **«Скинути свої»** повертає обраним те, що визначила апка;
* Esc спершу знімає позначки, вдруге — виходить із режиму.

Зміна фільтра звужує вибір до того, що видно: позначити, перешукати й
випадково змінити невидиме — неможливо.

## Правило руками

**Ще → Власні категорії.** Поле «містить» тепер підказує назви з вашої
ж історії — з кількістю операцій і сумою поруч. Вибрана назва одразу
скорочується до спільної частини («CLOUDRUN* 5V5FYU5» → «CLOUDRUN»),
інакше правило покрило б одну операцію з двадцяти. Під рядком видно,
скільки операцій зачепить. Поруч — підкатегорія, її підказки йдуть за
вибраною категорією.

### Умови, ширші за назву

«Viktor Z.» — це і оренда щомісяця, і випадковий переказ тій самій
людині. Назва в них однакова, тож правило вміє ще дві умови, і всі
вони мусять збігтись разом:

* **рахунок** — та сама картка, з якої платите за житло;
* **сума** — `5919` (рівно), `>2000`, `<500`, `5000-6500`, `~5900`
  (±10%).

Обидві є і в картці операції («…і лише за рахунком», «…і лише на
суму»), і у формі в налаштуваннях. Лічильник під полями рахує рівно
те, що зробить правило, і чесно попереджає, якщо сама операція під
умови вже не підпадає. У списку правил поруч видно, скільки операцій
кожне зачіпає зараз.

## Валюта показу

**Ще → Валюта:** гривня, долар або євро. Усе всередині зберігається в
гривні — валюта тут лише лінза: суми діляться на курс під час
малювання, тож перемикання не змінює жодного збереженого числа
(ліміти й підписки теж лишаються в гривні).

Поруч із головними сумами на **Огляді** дрібним стоїть друга валюта:
при гривні — долар, при доларі чи євро — гривня. Курс — живий від
банку; якщо його ще немає, апка бере той, що вивчила з ваших валютних
покупок, а якщо немає й такого — просто не показує другу валюту
замість того, щоб вигадати курс.

## Графік і рахунки

* Клік по стовпцю у «Витратах по днях/тижнях/місяцях» відкриває **всі
  операції цього проміжку** — і витрати, і надходження. Клікати можна
  по всій колонці, не тільки по самому стовпчику.
* Витрати тепер **сині**, надходження — **зелені**.
* Картку «Рахунки» можна згорнути кліком по заголовку; загальна сума
  лишається видною в шапці.

## Перемикання вкладок

Світло тепер не «доїжджає» взагалі: за секунду після запуску апка тихо
домальовує вміст усіх вкладок і трасує карти світла для них наперед,
тож перший клік по будь-якій вкладці отримує готові тіні в тому ж
кадрі. Якщо карта таки спізнюється (нова розкладка посеред роботи),
вона перетікає плавно за чверть секунди, а не перестрибує.

Швидке по-справжньому: у 1.9.4 разом зі «склом у тому ж кадрі»
найдорожча частина кадру — трасування карти світла (~300 мс) —
випадково переїхала прямо в обробник кліку, і перемикання висло до
секунди. Тепер синхронно малюється лише геометрія плит (~1 мс) зі
старою картою світла, нова трасується у фоні, а готові карти
кешуються — повторні перемикання не трасують нічого. Буфер полотна
сталого розміру, тож перемикання вкладок більше не перезавантажує
сцену в GPU. Виміряно: клік 12–44 мс замість 300–1100.

Миттєве, без анімації. Заїзд розділів пробували — і прибрали: рух
тягнув за собою весь текст, а скляні панелі за ним не встигали, тож на
кожному перемиканні екран перезбирався на очах.

Смуга періоду («Місяць / 3 місяці / …») є лише там, де вона щось
робить: **Огляд**, **Категорії**, **Операції**. У **Кошторисах**,
**Підписках** і **Ще** її немає — кошторис рахується за своїми датами,
підписки живуть у майбутньому, налаштування поза часом.

## Кошториси

Вкладка «Бюджети» стала «Кошторисами»: місячні ліміти прибрано разом
із перемикачем «Місячні ліміти / Кошторис проєкту» — лишився сам
кошторис проєктів.

## Повернення коштів

Скасоване замовлення приходить із банку як **зарахування** від того
самого мерчанта. Апка розпізнає його за двома ознаками разом: у
зарахування є MCC (тобто воно від торговця, а не від людини) і в
історії є витрата з такою самою назвою.

Таке зарахування **не рахується доходом** — воно зменшує витрати тієї
категорії, куди пішла покупка. У списку поруч із назвою стоїть `↩`, у
картці видно, за яку саме покупку повернули, а в покупці — скільки
повернулось і чи повністю.

Раніше, коли сума й час збігались, повернення склеювалось із покупкою
в «переказ між своїми рахунками» — так Glovo зі Steam опинялись у
«Між рахунками». Тепер повернення розпізнаються **першими** й під
пошук пар не потрапляють. Скільки їх — видно в **Ще → Якість даних**.

**Назва повернення рідко збігається з назвою покупки.** Банк пише
«Скасування. PayPal» проти «PayPal», та ще й на іншу гривневу суму —
курс за тиждень зʼїхав. Тому апка порівнює очищені назви (без слів
«скасування», «повернення», «refund») і суму **в валюті операції**:
499,99 $ туди й назад — найнадійніший доказ. Вікно пошуку — 90 днів.

**Якщо не вгадала — скажіть самі.** У картці будь-якого зарахування є
кнопка **«Це повернення»**: вона показує покупки за останні пів року,
згори — ті, де сума у валюті збігається. Вибрана покупка віддає
поверненню свою категорію. Кнопка **«Це не повернення»** знімає
автоматичну позначку. Ваше слово сильніше за здогад і переживає
повторний розбір виписки.

## Куди йдуть гроші

Картка на **Огляді** розгортається на місці: клік по рядку показує
підкатегорії, клік по підкатегорії відкриває саме ці операції.
Стрілка ↗ праворуч від назви веде у «Категорії», як було раніше.

## Тека з даними

**Ще → Застосунок → Змінити теку.** Дані **переносяться** (не копіюються),
тож двох однакових копій не лишається. Тека переживає перевстановлення
апки; поклавши її в OneDrive, Google Drive чи Dropbox, отримаєте
синхронізацію між комп'ютерами.

Якщо в цільовій теці вже лежать дані «Грошей», апка спитає: працювати з
тамтешніми чи перенести туди свої. Після зміни — перезапуск.

⚠️ Не тримайте апку відкритою одночасно на двох машинах: хмара не вміє
зливати зміни й лишить ту версію, яка збереглась останньою.

## Чому опитування, а не вебхук

Вебхук Monobank вимагає постійно доступного HTTPS-адреса, на якому лежить
ваш токен. Це десктопна апка на одній машині — сервера немає й не буде.
Банк віддає виписку одразу після операції, тож опитування дає ту саму
свіжість без жодної інфраструктури й без токена деінде, крім вашого
комп'ютера.

## Перезбирання

### На Windows (звичайний шлях)

```powershell
# Rust:  https://rustup.rs
# Node:  https://nodejs.org
npm install
npm run build
# → src-tauri\target\release\bundle\nsis\Гроші_1.31.7_x64-setup.exe
```

### З Linux (як зібрано цей інсталятор)

```bash
apt-get install -y nsis llvm lld clang libayatana-appindicator3-dev
rustup target add x86_64-pc-windows-msvc
cargo install cargo-xwin --locked
npm install
npm run build:win
```

`libayatana-appindicator3-dev` потрібен не для Windows-збірки, а тому що
бандлер Tauri перевіряє наявність трей-бібліотеки на **хост-системі** й
без неї падає.

MSI зібрати з Linux неможливо — WiX працює лише на Windows. NSIS працює.

```
  src/mono.rs        клієнт API: ліміт 60 с, вікна по 30 діб
  src/store.rs       JSON на диску, запис через тимчасовий файл
  src/update.rs      пошук новішої збірки в теці або за адресою
  tauri.conf.json    вікно, іконки, NSIS
build_desktop.py     перетворює браузерний шаблон на десктопний
```

Головний скрипт апки синхронний і читає `store.get()` просто в тілі
функцій, а дані з диска приходять асинхронно. Тому він лежить у
`<script type="text/plain">` і виконується вручну — після того, як
`desktop.js` дочитає все з диска. Так не довелося переписувати три
тисячі рядків на `await`.
